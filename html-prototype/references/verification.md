# 原型验收参考

按改动影响选用。小型改动可以把证据和结果写在交付说明里。复杂项目可单独保存记录，并与需求条款关联。

## 原页面与改动记录

| 记录 | 写到什么程度 |
|---|---|
| 页面证据 | 端、入口路径、页面与状态、核查版本或日期、适用角色和配置、授权截图或可复查来源 |
| 渲染条件 | 记录 CSS 视口、缩放和滚动位置。移动端按需要补充设备像素比、浏览器栏和安全区 |
| 改动对照 | 原位置、需求依据、新增或调整的行为、相邻需保留的区域、验收方法 |
| 已知缺口 | 未核实的页面或状态、影响和参考材料的适用范围 |

比较页面外壳、导航、内容宽度、字体、间距、固定区和主滚动区域。PC、移动 Web 和原生 App 按各自的约束校验。来源截图可以证明可见布局。既有的保存、权限和数据规则需要相应的行为或文档证据。

## 用一次操作追到结果

示例使用虚构的图书借阅站点。需求是在借阅页显示由管理员维护的借阅须知，且仅在选定分馆生效。

| 前置与操作 | 应观察到的结果 |
|---|---|
| 从空配置进入后台，填写须知，为分馆 A 启用并保存 | 分馆 A 的借阅页显示已提交文本。重开编辑页可见已保存的内容和范围 |
| 编辑文本后取消，再打开借阅页 | 已提交的文本继续生效，草稿未写入 |
| 在分馆 B 打开借阅页 | 分馆 B 保持该场景预期的默认显示 |
| 停用后再次打开分馆 A 的借阅页 | 须知按规则隐藏 |
| 下载单个 HTML 到空目录，离线重复主路径 | 样式和素材可见，配置与借阅页的联动仍可操作 |

同一文档里的配置视图和使用视图可以共享内存中的状态。若需求明确要演示刷新后回显或跨窗口联动，单独在最终打开方式下验证。通过本地文件直接打开时，浏览器对存储和跨窗口共享的处理可能不同。按验证结果选择可用方案，并写清演示范围。

## 验收记录

每条记录列出前置条件、实际操作、预期结果、观察结果及结论。用会暴露当前设计问题的数据检验边界，例如长文本、空列表、失效配置或不匹配的角色。视觉差异记录页面、状态和处置结果，问题修复后重新走受影响的操作。

离线验收时检查浏览器控制台和网络记录，定位脚本错误、资源缺失及残留请求。检查 DOM 结构中的弹窗、滚动和固定区域，并在浏览器中实际展开和操作。若文档预览只支持静态展示，确认下载入口可取得已验收的 HTML，在交付说明写明可交互的打开方式。
