# 单文件 HTML 实现

## 把基线落实成可编辑的页面

有现成代码时优先复用经过核对的布局、组件和样式。只给截图时，用 HTML 元素重建页面结构，用 CSS 实现间距、对齐、字体、滚动与状态。原型为空白项目时，原生 HTML、CSS 和 JavaScript 足够。较复杂的原型可以分文件开发，最终将代码和依赖的素材内嵌到一个 HTML。

布局从外往内建立。先做页面外壳、固定区、内容宽度和列，再做表格、表单与弹窗。用表格表达表格数据，用实际按钮、输入框和弹窗提供操作。字体优先使用常见系统字体。获得授权的图标、照片和小块专用素材可以内嵌 SVG 或 data URI。保留原文案、控件顺序和选中状态，记录需要替换的素材或权属未明确的部分。

## 让操作走到结果

- 从实际用户入口完成任务。列表页涉及搜索、筛选和分页时，从同一数据集合计算显示结果和总数，并同步空态、页码及跳页边界。示例数据的规模应足以重现相关状态。
- 编辑使用独立草稿。保存后更新统一数据源，重开时读回。取消、关闭和校验失败应按验收约定保留上次已提交值。删除、导入和批量动作须有可定位的处理范围与操作反馈。
- 配置与使用视图共享同一份状态。涉及多个项目或角色时，分别验证适用与不适用的情况。涉及任务或失败重试时，明确状态变化、重复点击和关联结果的行为。
- 截图以外的业务语义用用户规则或可核实资料支持。为评审补充的规则标为演示设定。文件下载可用本地 Blob，上传校验可读取用户主动选择的文件。保存、后台任务和权限均按本地演示范围说明。
- 交互状态适用时覆盖键盘焦点、弹窗关闭后还焦、无数据、加载或失败。交付稿从中性的默认状态打开。避免在产品主界面加入过程说明或调试工具。

## 导出后重新验收

把最终 HTML 单独放入空目录，通过浏览器直接打开。CSS、脚本、字体和图片应在此条件下可用。模块依赖、相对图片、浏览器本地文件限制以及运行时请求都可能造成仅在开发服务器上可用。静态检查和浏览器检查分开执行。若设置了本地持久化，按实际文件打开方式验证刷新行为，并说明数据如何重置。
