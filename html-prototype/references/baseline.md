# 页面基线与局部改动

## 先确认可用证据

用已授权的页面、可定位截图或现有原型，核对端、实际入口、日期或版本、角色、关键状态。对不上时记录差异。单张截图可以证明其所见布局和文案。保存、返回、权限、失败反馈和刷新后的行为，分别使用相关操作证据或需求规则确认。

PC、移动 Web 和原生 App 各自保留符合其载体的外壳。记录 CSS 视口、缩放和滚动位置。移动端按需区分 CSS 像素、设备像素、浏览器栏与安全区。桌面截图缩窄后的效果只能作为一种测试条件。

## 测量截图并确定视口

1. 以原始尺寸打开图片，记录像素宽高、截图边界与页面状态。分清整页、视口裁切、浏览器外壳与设备状态栏。只复原截图覆盖或有证据的范围。
2. 选定目标 CSS 视口和设备像素比（DPR）。尺寸已知时，用截图坐标除以 DPR 得到 CSS 坐标。只有图时先用几个可信的尺寸锚点估算比例，例如页头、表头与重复行高，并在验收中标注推断。
3. 测量页头高度、导航边界、内容卡四边、列起点、行高、固定栏和滚动范围。再比对文本、字重、颜色、间距、边框、圆角、阴影和控件状态。表格测列起点与至少两行高度，避免逐行累积误差。
4. 用语义化 HTML 和 CSS 先还原未改区域。整张截图用作比对证据。可编辑页面由元素和控件组成。需要复用截图素材时，仅截取有权使用的独立标识或图片，记录替换和裁切。遮蔽真实账号、内部标识或水印时，尽量保持原区域尺寸。
5. 保存原图与零改动基线的同尺寸浏览器截图。先修复会影响验收的布局差异，再加入新功能。页面参考已经过授权且可本地跑通时，可直接用原版本截图和几何数据作基线。

## 在实现前写清改动

| 页面和状态 | 确认的现状 | 本次修改 | 验收 |
|---|---|---|---|
| 虚构图书借阅站点的移动端借阅页 | 书名下方是分馆选择器，底部是借阅按钮 | 在分馆选择器下新增已启用的借阅须知 | 分馆 A 出现须知。分馆 B 保持原布局，借阅按钮可见可操作 |

先校准保留区域的几何尺寸、导航、控件顺序、内容密度和固定区。按改动对照加入变化，并检查新内容是否挤压邻近操作或改变滚动。完整截图用于对照。用实际 HTML 构造需要操作的按钮、表格和弹窗。

## 验证原样还原和局部改动

对需要重建的页面，先用原图与浏览器渲染结果核对外壳、字体、控件和关键布局；证据取自历史截图时，在结论注明截图日期和适用状态。接着用同一浏览器、视口、状态与滚动位置比较还原稿和迭代稿，检查改动是否只落在计划区域。能做像素对比时，预先标明改动区域、容差和判定办法。使用 DOM 几何检查判断控件是否移位，再用像素差检查渲染变化。展示原图、基线稿和迭代稿，方便区分还原偏差和需求增量。

## 收到反馈后复查

将源图与实际浏览器截图并排或叠看，按布局、组件、字体素材、固定区和交互记录差异。对同类偏差先查共享的样式或组件，再复查受影响页面。证据缺失时标注具体页面和状态。探索稿可展示新设计，正式还原结论以核实范围为准。
