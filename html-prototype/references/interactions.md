# 状态与交互

## 先画出一次真实任务

从入口走到结果，记录哪些动作只是编辑草稿、哪些产生提交、哪里读回结果。对会改变结果的字段写清来源、默认值、输入限制、作用范围和生效时机。按任务选择相关分支即可。

| 操作条件 | 应可观察的结果 |
|---|---|
| 首次进入且无数据 | 能沿入口创建或完成前置条件，空态能解释下一步 |
| 填入合法值并确认 | 提交后可在列表、详情或使用端看到结果，再次打开可读回 |
| 编辑后取消或关闭 | 上次已提交内容仍有效，草稿按当前规则处理 |
| 输入不合法、请求失败或权限不足 | 保留本次任务允许保留的输入，反馈提示下一步 |
| 配置仅对部分对象生效 | 各验证一个适用和不适用样例，检查对象切换后的结果 |

## 多视图从同一份状态读取

区分草稿、已提交数据和界面选择。配置与使用端视图从同一份演示状态读取，状态更新走同一处写入逻辑。把选中的对象与记录标识对应起来。验证提交后的下游视图、重开回显和取消三个结果。涉及停用或权限时，再验证可用条件变化后的路径。

单文件、单窗口原型可以使用内存状态，重开会回到初始样例。要求刷新回显或跨窗口时，在浏览器直接打开文件的条件下测试存储行为，记录实际支持的范围。浏览器对本地文件存储的处理可能不同。

## 控件要可操作

优先使用原生标签、按钮、表单和对话框。用 Tab 检查主路径顺序和可见焦点。打开弹窗后检查焦点进入、Esc 或取消，以及关闭后能回到触发位置。禁用提交时，提供能帮助用户完成下一步的反馈。演示需要支持空态、失败或多个角色时，通过可重复到达的正常操作或独立评审区触发。
