# HTML 产品原型

按用户指定的语言交付能从入口走到结果的原型。本 Skill 提供截图还原、HTML 实现及验收所需的方法和脚本。业务规则来自用户、原页面和可核实资料。先判断新设计、既有产品新增页面、局部迭代或验收，并按改动和风险裁剪流程。

## 定位任务与页面

**既有页面局部迭代：先还原，再加功能。** 有可复用的原页面时，以原版本作为基线。需要重建时，先在浏览器对照原页面，校准保留区域，再实现改动。按本次范围保留原有导航、布局、字段顺序、组件、默认状态和行为。

- 写清角色、入口、用户任务和结果。把会改变操作或结果的规则落实为验收场景。用已有资料解决可查事项，必要时标注推断和未决规则。
- 新设计从主任务和已有设计约束出发。既有产品新增页面时先核对父菜单、进入和返回路径、可复用组件。局部迭代先核实目标端、角色、版本、视口和关键状态，再列原位置、改动、相邻影响和验收方法。
- 区分能从截图核实的布局、能从规则核实的行为，以及需要实测的结果。缺证据时继续已核实的部分，未知区域可交明确标注“基线未核实”的阶段稿。
- 遇到截图还原、局部修改或多端适配时，按[页面基线与局部改动](references/baseline.md)确认视口、测量锚点，保留可单独打开的基线稿。

## 实现交互和数据结果

- 依照[单文件 HTML 实现](references/implementation.md)把页面和状态做成可编辑的 HTML、CSS 和 JavaScript。用真实控件和合成数据走通主路径与影响结果的分支。
- 涉及列表与详情同步、权限、编辑和取消、配置生效、多个角色或端共用数据时，读[状态与交互](references/interactions.md)。先明确状态作用域和生效时机，再选择演示状态存储方式。
- 使用用户提供和授权的素材。保持版式、文案和控件可编辑。测试状态入口、开发备注和重置演示数据放在独立评审区或可关闭的标注层。
- 导出一个 HTML，内嵌必要的样式、脚本和素材。核心任务应能在浏览器直接打开文件时离线操作。需要加载服务的探索稿应在实际交付方式中明确依赖。

## 验收并交付

1. 将最终 HTML 单独放进空目录，用浏览器打开实际交付版本。按[验收方法](references/verification.md)走一次主路径和本次相关的反例。
2. 各目标端分别验证，局部迭代用同视口、同状态和同滚动位置对照。修复后复查关联页面和交互。
3. 用可用的浏览器工具操作实际交付文件。Skill 自带可选的[隔离浏览器检查](scripts/verify_browser.cjs)、[截图差异检查](scripts/compare_images.py)和[静态资源检查](scripts/check_offline.py)，参数与回退方法见[验收方法](references/verification.md)。
4. 交付 HTML 和实际验证结果，说明端、视口、关键路径、模拟范围和未验证项。随 PRD 交付时，标清对应章节和版本，实际打开附件或下载件核对。
