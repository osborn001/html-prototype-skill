# HTML 产品原型

交付用户能直接打开、走完关键任务的单文件 HTML。以本次需求明确的范围、规则和使用端为准。先用现有资料核实可查事项，再处理会改变设计结论的缺口。

## 1. 确定页面落点

- 写清用户从哪里进入、要完成什么、结果在哪里查看。列出受影响的端、页面和关键状态。
- **既有页面改动**：先用授权环境或经核实的截图确认入口、页面和状态。动手前记录原位置、本次改动、需保留的邻近区域和验证方法。只修改约定范围，沿用其他导航、布局、字段、组件和行为。
- **既有产品新增页面**：核对所属端、父菜单、相邻页面、复用组件和返回路径，标明新增部分。
- **从零设计**：以需求和已有设计约束为基准，记录影响主流程的设计假设。
- 对既有页面，按端确认基线适用的版本、角色、配置、视口和页面状态。缺证据时继续处理独立部分。受影响的探索稿标为“基线未核实”，核实后才能作为正式还原交付。

## 2. 实现可走通的原型

- 用可操作的 HTML 控件实现入口、表单、列表、弹窗和状态反馈。先校准需要保留的页面结构，再加入改动。整页截图仅用于对照，单独使用获得授权的素材。
- 从入口和必要前置条件走到结果，覆盖本次相关的空态、失败、取消或权限分支。输入和数据使用合成样例，按当前需求模拟行为。
- 涉及配置联动时，明确配置对象、适用范围和生效时机。让配置页和使用页读取同一份演示状态，实际验证保存、下游变化、回显、取消和不适用的情况。
- 产品页面保留用户完成任务所需的控件和反馈。状态切换、重置演示数据和开发说明放在独立评审区或可关闭的标注层。
- 样式和脚本内嵌。必要图片用 data URI 或内联 SVG，字体使用系统字体或授权可嵌入字体。最终文件的核心展示和交互须在本地直接打开、离线可用。

## 3. 浏览器验证与交付

- 实际打开最终文件，逐页核查本次涉及的端和关键状态。既有页面使用与基线一致的视口、缩放、状态和滚动位置比较。修正差异后复查受影响的页面与主路径。
- 单独将最终 HTML 放到空目录，在离线条件下打开，检查样式、素材及关键操作。记录测试过的范围，并明确模拟结果、真实接口验证情况和证据缺口。
- 交付 HTML 文件与简明验证结果。若同时交付 PRD，把验收过的源文件放在统一原型入口，标清版本、适用端和需求章节，并打开实际附件或预览核对版本及可用范围。

需要记录基线、编写验收用例或检查跨页面配置联动时，参阅[原型验收参考](references/verification.md)。
